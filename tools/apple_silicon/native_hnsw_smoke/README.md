# Native HNSW Smoke

This diagnostic target is the shortest path to executing Infinity's real HNSW graph build on Apple Silicon.
It compiles the repository's production HNSW algorithm, graph store, data store, plain vector store, result
heap, iterator, and invariant checks. Small module adapters replace unrelated server, persistence, sparse,
compression, and multivector dependencies. The L2 adapter calls Infinity's production `F32L2SSE` and
`F32L2SSEResidual` kernels, which SIMDe lowers to NEON on arm64. This target remains a development
diagnostic, not benchmark qualification evidence.

The deterministic workload inserts 1,280 16-dimensional vectors generated by `mt19937(0)`, validates graph
invariants, and requires at least 0.95 self-recall at one.

Configure with CMake 4.3 and Homebrew LLVM 20:

```sh
/private/tmp/infinity-native-tools/cmake-4.3.2-macos-universal/CMake.app/Contents/bin/cmake \
  -S tools/apple_silicon/native_hnsw_smoke \
  -B build/native-hnsw-smoke \
  -G Ninja \
  -DCMAKE_MAKE_PROGRAM=/Volumes/infinity-c0-retired-v14/prefix/Cellar/ninja/1.13.2/bin/ninja \
  -DCMAKE_C_COMPILER=/opt/homebrew/opt/llvm@20/bin/clang \
  -DCMAKE_CXX_COMPILER=/opt/homebrew/opt/llvm@20/bin/clang++ \
  -DINFINITY_NATIVE_CTPL_INCLUDE_DIR=/path/to/vit-vit-ctpl \
  -DCMAKE_OSX_ARCHITECTURES=arm64
```

Then build and run:

```sh
/private/tmp/infinity-native-tools/cmake-4.3.2-macos-universal/CMake.app/Contents/bin/cmake \
  --build build/native-hnsw-smoke --target infinity_native_hnsw_smoke
./build/native-hnsw-smoke/infinity_native_hnsw_smoke
./build/native-hnsw-smoke/infinity_native_simd_l2_smoke
./build/native-hnsw-smoke/infinity_native_hnsw_bulk_build_smoke
```

The SIMD smoke compares the production aligned and residual kernels with a double-precision reference for
every dimension from 1 through 513.

The bulk-build smoke executes the exact shared routine called by production `HnswHandler::InsertVecs`.
It constructs Infinity's `ctpl::thread_pool` inside the cold timing boundary and requires 12 created
participants, 12 production-policy tasks, a complete 12,288-vector range, graph invariants, and at least
0.95 self-recall at one. It is the contract-approved production bulk-build path, but it does not instantiate
the full `HnswHandler` variant or the Infinity server.

To add the matching one-thread stock FAISS 1.15.0 diagnostic, install the Homebrew `faiss` bottle and
reconfigure with `-DINFINITY_NATIVE_SMOKE_WITH_FAISS=ON`. Then build and run
`faiss_native_hnsw_smoke`. Its output is a rough bring-up comparison only; it is not final benchmark
evidence.

The same option adds `hnsw_native_dev_compare`. It generates one matrix and passes the same pointer to
separate Infinity and FAISS bridges, with both indices destroyed between runs. Positional arguments are:

```text
vectors dimensions M efConstruction efSearch chunkSize queryCount order participants buildGrain
```

`participants` constructs Infinity's production `ctpl::thread_pool` inside the cold-build timing boundary
and configures the FAISS OpenMP team. The reported Infinity thread count comes from the constructed pool.
The final positional field is retained for compatibility with older diagnostic command lines but must be
zero. Nonzero values are rejected because the shared routine always uses `HnswHandler`'s production bucket
policy.

It reports constructor-plus-build and insertion-call timing. This same-process tool is for rapid
development only and does not implement the fresh-process, mapped-input, recall, resource, thermal, or
statistical controls required by `docs/apple_silicon/benchmark_contract.md`.
